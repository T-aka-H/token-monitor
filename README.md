# Token Monitor

Claude Code のコンテキスト消費を「セッション → ターン → 原因」まで掘るローカル Web アプリ。

Claude Code の Input トークンは、その大半が `cache_read_input_tokens` — つまり**過去のやりとりの読み直し**です。
プロンプトを短くしても効きません。効くのは、不要になったコンテキストを持ち越さないこと。
このツールは、どのセッションが太っていて、**どのターンがそれを引き起こしたか**を特定します。

```bash
python3 cc_tokens_web.py
```

ブラウザが開きます。それだけです。

## なぜ「持ち越し」を見るのか

ターン明細に並ぶ「その時点のコンテキスト量」は単調増加するので、犯人が分かりません。
このツールは 2 つの指標を出します。

| 指標 | 意味 |
|---|---|
| 増加 | 直前ターンからのコンテキスト増分。そのターンが持ち込んだ量 |
| 持ち越し | 増加分 × 以降のターン数。**その 1 回の読み込みが、後で何度も課金された総額** |

10 ターン目の `+620k` は、残り 210 ターンで読み直されて **128M トークン**になります。
同じ `+620k` でも最終ターンならほぼゼロ。だから「いつ読んだか」が効きます。

## できること

- **SESSIONS** — セッション一覧。コンテキストの推移をヒート色のミニグラフで表示
- **TIMELINE** — 1 時間ごとの消費量（24H / 3D / 7D / 30D）と時間帯プロファイル
- **カレンダー** — 日別ヒートマップ。クリックで期間フィルタ（Shift+クリックで範囲指定）
- **4 段ドリルダウン** — 時間 → セッション → ターン → そのターンが呼んだツールと引数
- **ライブ監視** — 8 秒ごとに自動更新。作業中のセッションがしきい値を超えると警告
- **テーマ** — 8BIT / POP / LIGHT / DARK

## 設計上の約束

- **依存ライブラリなし。** Python 3.9+ の標準ライブラリのみ。CDN も使いません
- **外部送信ゼロ。** ログは読むだけ。ネットワーク呼び出しは一切ありません
- **読み取り専用。** `~/.claude` に書き込みません
- **localhost 限定。** `127.0.0.1` に bind し、`Host` ヘッダを検証します（DNS リバインディング対策）

## オプション

```
--dir   ログのルート（既定: ~/.claude）
--port  ポート（既定: 8765。使用中なら自動でずらす）
--no-open  ブラウザを自動で開かない
```

## 注意

このツールが表示する内容には、**あなたのプロンプト・ファイルパス・実行コマンドが含まれます**。
スクリーンショットを公開する場合は、`--dir` でダミーのログを指すか、内容を確認してください。

また、起動中はローカルの他プロセスから API を読める状態になります。
共有マシンで使う場合は、必要なときだけ起動してください。
