## 1. 描画性能（最重要）

### 踏んだ罠
1287 セッションの実データで **初期表示に25秒**かかり、ブラウザが応答を返せなくなった。
原因は一覧の全行を一度に DOM へ載せていたこと。行ごとにスパークライン SVG があるため、
矩形が 37,745 個、DOM 全体で 58,094 要素になっていた。

```
          修正前 → 修正後
初期表示   25.02s → 2.69s
DOM要素   58,094 → 3,196
SVG矩形   37,745 → 1,595
```

### 今のコードの防御
- `renderList()` は `SHOWN`（初期60件）までしか描かない。残りは「もっと見る」で +60
- `downsample()` の `target=36`（もとは64）。一覧の描画コストは **点数 × 行数** で効く
- 行の登場アニメーションは先頭20行のみ（`animate && i<20`）
- 絞り込み・期間変更・並べ替えのたびに `SHOWN=PAGE_SIZE` にリセット

### やってはいけない
- 全件描画に戻す
- スパークラインの点数を増やす
- 行に SVG 以外の重い要素を足す

仮想スクロールを入れるなら別だが、上位から見るツールなので段階表示で十分。

## 2. JSONL のパース

### 追記専用であることを利用している
`LogStore._parse(path, offset, state)` は**前回読んだバイト位置から先だけ**を読む。
そのため 8 秒ごとの自動更新でも 450 ターンのセッションを毎回全読みしない。

- テキストモードだと `tell()` が使えないので **バイナリで開いて `read()`**
- **書きかけの最終行は次回にまわす**（`data.endswith(b"\n")` で判定して切り捨て、offset も進めない）。
  Claude Code が出力中でもパースが壊れないのはこのため。壊れた JSON を混ぜても落ちないことを確認済み
- パースは行をまたいで状態を持つ（直前の人間の指示 / 投入された tool_result のサイズ）。
  差分読みのために `state` として持ち越している。ここを消すとラベルが欠ける
- ファイルが縮んだ場合（truncate）は先頭から読み直す

### `day` と `hour`
ターンごとにローカル日付・時刻を**パース時に1回だけ**計算して持たせている。
毎回の集計で `datetime` を回すと、数万ターンで自動更新が重くなる。

## 3. レイアウトの罠

### `<button>` は中身を縦中央に寄せる
カレンダーのセルを `<button>` にしたところ、日付の数字が中央まで下がって値と重なった。
実データ（`670.9M` のような桁数）で初めて目に見えるようになった。

**対策:** 日付・値とも絶対配置（`.day .d` は `top:6px`、`.day .v` は `bottom:6px`）。
`display:block` や `align-items` では解決しなかった。フローに頼らないこと。

### 角丸トークンは3種類ある
| 変数 | 用途 | pop での値 |
|---|---|---|
| `--r` | 大きいカード（`.win`） | 16px |
| `--r-s` | 容器（行・セル・テーブル） | 12px |
| `--r-p` | 錠剤（ボタン・チップ・バー） | 999px |

最初 `--r-s` を全部に使ったせいで、pop テーマでセッション行やカレンダーセルまで
錠剤形になった。**新しい要素を足すときは用途に合うトークンを選ぶこと。**

### 8bit テーマの枠
`box-shadow` を上下左右に4方向出して角だけ空ける手法（NES ダイアログ風）。
`--fr` / `--fr-s` / `--fr-x` に入っている。他テーマでは同じ変数が普通の枠線になる。

## 4. アニメーション

### 自動更新でアニメを再生しない
8 秒ごとに全部が踊ると読めない。`renderList(animate)` / `openSession(sid, silent)` の
フラグで、ユーザー操作のときだけアニメーションする。

### タイムラインはモーフィングと再構築を分けている
- 時間バケットの並びが前回と同じ（`TLKEYS` が一致）→ **`scaleY` だけ差し替え**て滑らかに変形
- 期間を切り替えてバケットが変わった → 組み直して左から順に立ち上げ

棒の高さは `height` 属性ではなく `transform: scaleY()` で制御している。
SVG の `height` を書き換えても CSS トランジションが確実に効かないため。

テーマ変更時は色が変わるので `TLKEYS=''` にして必ず組み直す。

## 5. タイムラインの時間軸

右端は **「最後に作業した時刻」に固定**している。現在時刻を基準にすると、
最後の作業が数日前だったとき「直近24時間」が空欄だけになるため。
見出しには実際の範囲（`7/21 00:00 - 7/27 23:00`）を必ず表示すること。

## 6. カレンダーの濃淡

日別トークンは極端に偏る（1日だけ10倍ということが普通に起きる）。
線形スケールだと他の日が全部同じ色に潰れたため、**平方根スケール**にしている。
順序は保たれるが、色の面積比は実際の量の比ではない。凡例とツールチップで補っている。

## 7. セキュリティ

### DNS リバインディング
`127.0.0.1` に bind するだけでは防げない。攻撃者が自分のドメインを `127.0.0.1` に
向け直すと、ブラウザは同一オリジンとみなして API を読める。ログにはユーザーの
プロンプトやファイルパスが含まれるため、これは実害になる。

`Handler._host_ok()` で `Host` を検証している。**エンドポイントを追加するときは必ず通すこと。**

```
Host: 127.0.0.1        → 200
Host: localhost        → 200
Host: evil.example.com → 403
```

### XSS
ファイル名・プロンプト・コマンドはすべてログ由来で、HTML を含みうる。
`"><img src=x onerror=...>` を実際に流し込んで、テキストとして表示されることを確認済み。
**テンプレートリテラルにログ由来の値を入れるときは必ず `esc()`。**
ツールチップは `textContent` を使っているので安全。

## 8. 動作確認のやり方

目視では実データ規模の問題が見つからない。DOM を計測すること。

```python
# playwright で計測する例
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b = p.chromium.launch(); pg = b.new_page(viewport={"width":1264,"height":1200})
    errs = []
    pg.on("pageerror", lambda e: errs.append(str(e)))
    pg.on("console", lambda m: errs.append(m.text) if m.type=="error" else None)
    pg.goto("http://127.0.0.1:8899/", wait_until="domcontentloaded")
    pg.wait_for_selector(".row", timeout=40000)
    print("DOM要素数:", pg.evaluate("document.querySelectorAll('*').length"))
    print("要素の位置:", pg.locator(".day .d").first.bounding_box())
    print("ERRORS:", errs or "none")
```

確認すべき観点:
- **JS エラーがゼロか**（`pageerror` と `console.error` を両方拾う）
- **要素が重なっていないか**（`bounding_box()` の座標で判定。目視しない）
- **DOM 要素数**（数千で収まっているか）
- **4テーマすべて**で崩れていないか
- **1000セッション超のダミーログ**でも初期表示が数秒か

ダミーログは `~/.claude/projects/<任意>/<uuid>.jsonl` の形式で、
`{"sessionId","timestamp","cwd","type":"assistant","message":{"model","content","usage"}}` を
1行1レコードで書けばよい。`usage` に4種のトークン数を入れる。
